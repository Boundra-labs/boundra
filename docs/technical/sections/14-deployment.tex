\chapter{Deployment and operations}\label{ch:deployment}

Boundra ships as Docker images built from one Dockerfile, and can run in two ways: a Docker Compose stack on any server, or Render. Both use the same images and the same reviewed Base Sepolia manifest.

\begin{itemize}
  \item Settings come from \code{deploy/.env} (created by \code{node scripts/setup.mjs --deploy}; secrets readable by the operator only). The manifest is mounted read-only from \code{deploy/manifests/}.
  \item With a public \code{APP\_DOMAIN} whose DNS points at the host, Caddy obtains and renews Let's Encrypt certificates itself.
  \item Releases: tagging a green commit \code{v*} publishes \code{boundra-\{web,api,worker,migrate\}} images to GHCR. Each image carries its release identifier, which \code{/status} and the health endpoints report.
  \item A backup is taken before every upgrade; migrations only move forward, so a rollback that crosses a migration restores the backup.
\end{itemize}

\begin{caution}[Free-plan limits]
A free service sleeps after about 15 minutes without visitors, and the agent sleeps with it; the next visit takes about a minute to wake it. Free instance hours are limited per month, and the free database expires after Render's free period. Switching the service and database to paid plans removes these limits without other changes.
\end{caution}

\section{Settings that matter}

\begin{btable}{@{}P{5.3cm}L@{}}
\headrow \thead{Setting} & \thead{Purpose}\\ \midrule\endhead
\code{DEPLOYMENT\_MANIFEST\_PATH} & The reviewed manifest; without it the worker only observes.\\
\code{WEB\_ORIGIN} & The exact public origin; sign-in messages and the Origin check depend on it.\\
\code{OPERATOR\_ADDRESS} & Boundra's agent, public address only (API).\\
\code{OPERATOR\_PRIVATE\_KEY} & The agent's own key (worker only). Never the owner's, deployer's or risk admin's.\\
\code{EXECUTION\_ENABLED}, \code{ATTEMPT\_ENCRYPTION\_KEY}, \code{MAX\_GAS}, \code{MAX\_FEE\_PER\_GAS\_WEI}, \code{MAX\_PRIORITY\_FEE\_PER\_GAS\_WEI} & Required for \code{execute} mode. Fee caps are ceilings: above them the worker skips the action rather than overpay.\\
\code{MONITOR\_BATCH\_BLOCKS} & Risk-scan size (180 fits the public RPC).\\
\code{ADMIN\_ADDRESSES} & Wallets allowed to use admin routes (lowercase).\\
\code{LLM\_PROVIDER}, \code{LLM\_MODEL}, \code{LLM\_API\_KEY} & Optional wording provider (chapter~\ref{ch:llm}).\\
\code{TRUST\_PROXY} & True only behind a trusted proxy (Caddy or Render).\\
\end{btable}

\section{Checking a deployment}

\begin{enumerate}
  \item \code{/status} reports \code{"status": "ok"} and \code{"worker": "execute"}; \code{monitor\_only} means a worker setting is missing or rejected, and the logs name which (never its value).
  \item \code{/api/v1/health/ready} reports the database as connected and a fresh worker heartbeat.
  \item The worker logs show \code{Worker mode: execute} and no repeated monitor failures. On first start the risk monitor needs about 40 minutes to catch up from the deployment block.
\end{enumerate}
