\chapter{Web app}\label{ch:web}

The web app (Next.js 16, React 19, wagmi 3, viem) is where owners do everything: sign in, set up their executor, describe a goal, answer ACCE's questions, review and approve the mandate, sign it into the contract, then watch and control the agent.

\section{Wallet transactions done honestly}

Every owner transaction is built from the exact values the API returned (amounts as exact base units, never rounded) and goes through the same handling:

\begin{itemize}
  \item The network guard keeps the wallet on chain 84532 and offers to add or switch the network.
  \item Before asking the wallet, the app simulates the call and sets its own gas limit, instead of trusting a wallet estimate made against a different node.
  \item States are shown honestly: waiting for the wallet, sent, confirmed, or reverted. A sent transaction is never shown as done until it is confirmed, and wallet errors are reported in plain language.
  \item Balances, positions and mandate status shown to the owner come from chain-confirmed state through the API.
\end{itemize}

\section{Reviewing a mandate}

The review screen is where consent happens, so it shows everything that will be enforced: the selected vault, every cap, the lockup, the expiry, the operator (marked ``your own agent'' when the owner named one), every notice and the testnet labels. Approval sends the \code{previewHash} of exactly that preview. Any edit produces a new revision that must be reviewed again.

\begin{keypoint}[Plain language, exact numbers]
Agent escalations, holds and refusals are explained in words an owner understands (for example why the agent is waiting, or why funds cannot leave a locked vault yet), while every amount stays exact. The activity timeline links to the block explorer only for real transactions.
\end{keypoint}
